# Agents

The bundler runtime is organised into small, single-purpose agents. Each one
owns a well-defined slice of the workflow so that new behaviours can be added
or swapped in with minimal coupling.

## CLI Agent (`bin/bundler`)
- Parses CLI flags (config, manifest, watch, verbosity) and configures global
  logging through `Ronanchilvers\Bundler\Cli`.
- Instantiates the remaining agents and wires their event subscriptions.
- Exposes a watch mode that keeps the process alive and delegates rebuilds to
  the watcher agent.

## Configuration Agent (`src/Builder.php`)
- Translates `bundler.yaml` into runtime objects.
- Creates `Format\FormatterInterface` instances (and optional decorators) for
  each bundle.
- Resolves bundle file paths relative to `globals.source`, raising early if a
  file is missing so failures are obvious.
- Emits configuration lifecycle events: `CONFIG_BUNDLE_START` and
  `CONFIG_BUNDLE_END`.

## Processing Agent (`src/Processor.php`)
- Iterates the bundles generated by the builder and calls the configured
  formatter (`FormatterInterface::render`).
- Emits `BUNDLE_PROCESS_BEFORE`, `BUNDLE_PROCESS_AFTER`, and
  `BUNDLE_PROCESS_ERROR` so listeners can react, mutate, or report failures.
- Collects rendered bundles into a `Manifest`, which is later stored on disk.

## Output Agent (`src/Output/Handler*`)
- Factories in `Output\Handler::factory` create specific handlers (currently
  filesystem-oriented) using the configuration gathered by the builder.
- Handlers are responsible for persisting rendered bundles and can emit output
  lifecycle events (`OUTPUT_HANDLE_BEFORE`, `OUTPUT_HANDLE_AFTER`).

## Manifest Agent (`src/Manifest.php`)
- Stores the final bundle payload (`content`, `integrity`, metadata) under the
  logical bundle name.
- Persists the manifest cache file used for cache-busting and downstream
  template helpers.

## Watcher Agent (`src/Watcher/File.php`)
- Polling-based file watcher that monitors the config file (and any additional
  files listeners register).
- Emits watcher lifecycle events (`WATCHER_START`, `WATCHER_FILE_MODIFIED`,
  `WATCHER_STOP`) and invokes the CLI callback to trigger rebuilds.
- Designed so future implementations (e.g. OS-level notifications) can abide
  by the same contract.

## Event Agent (`src/Events`)
- `Dispatcher` manages event listeners and supports both variadic callbacks
  (`emit`) and richer event objects (`dispatch`, future work).
- `EventNames` centralises all constants, keeping stringly-typed event usage in
  one place and making extension points discoverable.

## Extending / Authoring New Agents
- Prefer composing new behaviour via events or decorators before editing core
  agents; this keeps the CLI flow stable.
- New formatters belong under `src/Format/Formatter`, optionally paired with
  decorators in `src/Format/Decorator`.
- Additional output handlers live under `src/Output/Handler`; register them in
  the handler factory.
- If you need to react to file changes beyond the config file, subscribe to
  watcher events and call `File::addFile`.

## Operational Checklist
- Keep `bundler.yaml` canonical; downstream agents assume paths resolve after
  the placeholder expansion handled by `Path::placeholders`.
- Run the CLI in verbose (`-v`) or debug (`-d`) mode when wiring new agents so
  the lifecycle logging highlights event order.
- Regenerate the manifest (`bin/bundler -c bundler.yaml`) after modifying
  formatter or handler logic so tests and fixtures stay in sync.
